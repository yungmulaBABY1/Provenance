CITATION-NETWORK COMPLIANCE-GATE PILOT
======================================

CLASS
-----
FAIL-class repair.

Prompted by:
An observed live-run failure in which required citation-network sections were
present in the prompt but absent from the output.

WHAT THIS PATCH CHANGES
-----------------------
1. Requires exact analytical headings for the pre-audit confirmation and Sections
   A through K.
2. Requires exact headings for final Artifacts 1 through 10.
3. Adds a Completion Ledger immediately before the standardized finding table.
4. Forbids silent merging of required sections.
5. Permits N/A only under the exact heading and with a specific reason.
6. Withholds the substantive final verdict when any applicable section or
   Artifact 1 through 9 is omitted.
7. Keeps the standardized finding table as the actual final section.

WHY THE LEDGER IS CHECKABLE
---------------------------
The ledger is not trusted as a judgment self-report. Its entries can be checked
against exact headings in the output. The exact-heading rule is the primary
mechanism; the ledger is a visible summary.

MECHANICAL CHECKER
------------------
Run:

  python check_citation_network_output.py audit-output.txt

Exit codes:

  0  all required headings present
  1  one or more required headings missing
  2  usage error

The checker tests presence only. It does not determine whether a section was
substantively completed or whether an N/A decision was justified.

LOCAL CHECKER TEST
------------------
PASS:
- A deliberately incomplete output was rejected with 22 missing headings.
- A fixture containing all 25 required headings passed.

LIVE PILOT STILL REQUIRED
-------------------------
Run the revised prompt on one compact citation-network case before propagating
this mechanism to other prompts.

Pass conditions:
1. All exact headings appear.
2. The Completion Ledger appears.
3. No applicable section is silently merged or skipped.
4. N/A sections state a concrete reason.
5. If any required section is absent, Artifact 10 is withheld as instructed.
6. The mechanical checker exits 0 for a complete run.

Diagnostic interpretation:
- Ledger and headings both present: wording may have fixed the compliance gap.
- Ledger present but sections missing: model can self-report the failure; exact
  heading check catches it.
- Ledger itself omitted: likely output-burden or instruction-salience problem,
  not a missing reminder. Do not propagate; consider staged execution.
- Small case passes but large case fails: likely output burden. Split the audit
  or compress intermediate tables rather than adding more compliance language.

NOT PROPAGATED
--------------
This gate has not been added to construct validity, internal validity, claim
extraction, counter-audit, or media prompts. Propagation waits on the live pilot.
